# Tide Admin — Mission

## Purpose

Tide Admin 是一套高质量、开箱即用的 **多租户中后台脚手架与可二开底座**。

它要解决的问题是：市面上许多中后台框架扩展性、代码规范与开发体验难以兼得；基础版能力残缺或业务闭环不足；交付导向下优秀实践难以沉淀。Tide Admin 以持续打磨的通用业务能力与工程规范，让团队（以及 AI Agent）在舒适的开发体验下快速启动并长期演进 B 端系统。

愿景：把 Tide 用到工作场景时，不只提高效率，更让编程工作多一点「甜」——尤其在 AI 编程时代，让助手能「学习」优雅规范、「写出」优质代码。

## Users

按优先级：

1. **后端 / 全栈开发者** — 需要可扩展、规范清晰的脚手架，快速开工专属中后台。
2. **AI Agent 使用者** — 依赖仓库内规范与规格，驱动 Agent 持续改代码而不漂移。
3. **多租户 SaaS 产品团队** — 需要租户、权限、组织等底座能力，在此之上做业务二开。
4. **初创 / 中小团队** — 用开箱即用的通用中后台能力减负，聚焦自身业务。

## Solution

提供前后端一体的中后台框架：SaaS 多租户、RBAC 与数据权限、用户 / 角色 / 菜单 / 部门、消息与公告、文件、字典与系统配置、开放 API、任务调度、代码生成等，形成可落地的业务闭环；同时通过模块化平台域（如 iam、tenant、file、job、ops）与工程规范，支撑人和 AI 长期协作扩展。

## Differentiators

- **体验与规范优先**：不只堆组件，强调可读性、分层清晰与可复用的业务设计。
- **业务闭环**：通用中后台能力逻辑完整，减少「样板化却不可用」的缺口。
- **AI 友好**：规范、结构与规格可被 Agent 稳定消费，适合 Spec / Agent 驱动开发。
- **可二开的多租户底座**：在脚手架之上，可作为 SaaS 管理端底座持续演进。
- **可持续打磨**：开源协作沉淀实践，对抗交付压力带来的架构腐烂。

## Success

同时满足：

1. **快速启动**：克隆后可本地跑通；通过品牌与配置定制，即可启动专属中后台。
2. **可持续扩展**：通用能力闭环；文档与规范足以让人与 AI 在扩展时保持架构一致、避免腐化。
3. **可二开底座**：不仅是脚手架，更是可二开的多租户 SaaS 管理端底座。

## Non-goals

- **不追求微服务拆分**：保持模块化单体（或等价的清晰模块边界）优先；不为拆服务而拆服务。

## Current focus

按优先级推进：

1. **打磨开源脚手架体验与规范** — 稳定、舒适、可交付。
2. **强化 AI 友好** — 规范、规格与可生成性，降低 Agent 协作成本与漂移风险。
3. **完成 platform 领域重构与分层治理** — 持续收敛领域边界与模块职责。
